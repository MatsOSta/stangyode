01 / STACK

The stack is a set of seams.

Models are only one layer. The reliable system connects intent, harness, execution, capabilities, context, control, and evidence.

SYSTEM LAYERS / 13 SEAMS

  1. 01Intelligence & agencyThis layer separates model capability from agency: objectives, inference budgets, and selection policies become observable engineering choices.
  2. 02Harness & executionIt covers the control plane around a model and the environments in which actions, code, and computer interaction are executed.
  3. 03OrchestrationThis layer distinguishes model-led delegation from declared workflows and combinations of the two.
  4. 04DurabilityThese mechanisms make long or interrupted work recoverable without confusing history replay with duplicate side effects.
  5. 05CapabilitiesCapabilities are the concrete powers exposed to an agent, from tools and skills to runtime-integrated extensions.
  6. 06ProtocolsProtocols define boundaries between hosts, tools, resources, and agents; they are not interchangeable implementations.
  7. 07ContextContext engineering manages the bounded information visible now, including disclosure, compaction, sessions, and durable artifacts.
  8. 08Memory & retrievalMemory can survive a session; retrieval is one way to place selected information into the current context.
  9. 09GovernanceGovernance separates model-facing guidance from approvals, authorization, identity, and controls enforced outside the model.
  10. 10ObservabilitySignals here explain what an agent did, how it did it, and what operational cost or failure followed.
  11. 11EvaluationEvaluation turns desired behavior and production evidence into repeatable measurements of answers and trajectories.
  12. 12Agentic UIThis layer distinguishes generated surfaces from protocols that stream or declaratively render agent-facing interfaces.
  13. 13Development methodologyThese practices define how humans specify, supervise, test, and accept software built with coding agents.
Example implementations / expand
  • Model / intelligence: reasoning model + agent loop
  • Harness / execution: sandboxed code execution + tool policy
  • Orchestration: deterministic workflow with agentic decision step
  • Durability: Temporal-style event history and replay
  • Capabilities: MCP tools plus skills
  • Protocols: MCP for tools/resources, A2A for agent collaboration
  • Context: progressive disclosure and compaction
  • Memory / retrieval: working memory plus RAG
  • Governance: identity, permission layer, approval gate
  • Observability: OTel trace with trajectory events
  • Evaluation: offline trajectory eval plus online monitoring
  • Agentic UI: AG-UI events or A2UI declarative surface
  • Methodology: spec-driven, eval-driven agentic coding

Displayed stacks are examples, not required blueprints; layers overlap and some components are optional.

Intent is flexible. Execution should be legible.

Split judgement from known process. Let agents and A2A handle open-ended intent; let workflows handle known paths; reunite at tools, MCP, and external systems.
